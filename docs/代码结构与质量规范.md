# 代码结构与质量规范

## 目录职责

- `app/domain`：纯业务对象和端口，不依赖 AgentScope、FastAPI 或数据库。
- `app/application`：用例、Agent、工具和编排；只通过 domain 端口访问基础设施。
- `app/infrastructure`：SQL/JSON、Redis、Qdrant、模型网关、观测和韧性实现。
- `app/presentation`：HTTP、WebSocket、SSE/AG-UI DTO 与路由；不承载业务规则。
- `frontend`：React 页面和 AG-UI 客户端，只消费事件和结构化 API。
- `scripts`：离线评测、冒烟、压测和运维脚本，不被运行时导入。

## 修改规则

1. 新业务规则放在 domain/usecase，不放在路由或 React 组件。
2. 外部服务失败必须有明确降级，并记录结构化事件；不得伪造结果。
3. 写操作必须经过确认、幂等和持久化边界。
4. 新增配置必须有默认值、`.env.example` 项和测试覆盖。
5. 评测输入冻结，模型评测与离线安全契约分开；评测失败不得自动发布。

## 统一检查

```bash
make check
```

该命令依次执行 Python 语法检查、核心测试、离线评测契约和前端构建。
